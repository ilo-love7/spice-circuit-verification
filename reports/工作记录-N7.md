# 工作记录 · N7 SPICE 电路自动化仿真验证

> v1.0.0 · 2026-11-10

## §1 环境决策

- 提案工具 PySpice + ngspice。`pip install pyspice` 顺利（1.5）；**ngspice Windows 引擎**是主要障碍：
  - SourceForge 官方下载页被 Cloudflare 盾挡（脚本探测 403/挑战页），官方安装包（含 `libngspice-0.dll`）拿不到；
  - GitHub `Schemline-IC/ngspice-builds` v46 有 `ngspice-46-win64.zip`（6.06 MB），但只带 `ngspice_con.exe` **无共享库 DLL**；
  - 下载本身也要 `--noproxy * --connect-to github.com:443:<edge-ip>:443`（本机代理 502，边缘 IP 直连可用）。
- 决策：**PySpice 网表前端 + ngspice_con.exe 批处理 + 自研 raw 解析**三层结构。README/报告如实标注偏离"PySpice 共享库驱动"的原计划。

## §2 ngspice 批处理引擎调通

- `ngspice_con.exe --version` 在 Git Bash / PowerShell 下无输出且退出（SIGTERM），但 `-b -o log -r raw file.cir` **批处理模式正常**（0.06 s/circuit）。
- code model 报错：`spinit` 用相对路径 `lib/ngspice/*.cm`，安装根目录含中文（`D:\项目\...`）时加载失败 → 本项目电路（RLC+VCVS）用不到 XSPICE code model，直接移除 codemodel 行。
- raw 文件默认 binary；`set filetype=ascii` 必须在 **share/spinit**（不是 bin/spinit，后者不被读取）里取消注释。
- ASCII raw 的 `Values:` 段：point 首行 `idx  re,im`，后续 `nvars-1` 行 `\t re,im`；`Variables:` 行可能带扩展字段（`grid=3`），正则必须 `.*$` 兼容（首版漏了它导致只解析出 frequency 一列）。

## §3 理论 vs 仿真

- 所有传递函数节点法手推：SK 低通正反馈 C1 拓扑 `H = 1/(1+s(R1+R2)C2+s²R1R2C1C2)`；SK 带通接地 R 拓扑 `H = K·s/(RC)/(s²+3s/(RC)+1/(R²C²))`（Q=1/3 结构约束）。
- Butterworth 元件选择：R1=R2 时 `Q = √(C1/C2)/2` → C1 = 2·C2（注意方向：**C1 大 C2 小**，与直觉相反，仿真核对无误）。
- 运放 VCVS 技法：跟随器 `E1 out 0 b out 1e6`（out = 1e6·(b−out)）；反相 `E1 out 0 0 inv 1e6`。有限 A=1e6 理论修正 `−G/(1+(1+G)/A)` 与仿真**零误差**命中——验证了理想运放建模口径。
- 机器精度一致（1e-14 dB）确认了两件事：解析式推导正确 + ngspice 线性求解器 + raw 解析无损。

## §4 坑清单（复用价值）

1. **PySpice 1.5 `VoltageSource` 无 `ac` 参数**（`Unknown argument ac=1` / `.ac()` AttributeError）→ 网表后处理正则补 `AC 1`。
2. **numpy.float64 进 f-string 的 `!r`** 会渲染成 `np.float64(1000.35)` 直接毁网表（ngspice 报 unknown parameter）→ builders 所有槽位 `float(x)!r`。
3. **scipy `TransferFunction` 自动按首项归一**：`TransferFunction([1],[RC,1]).den` = `[1, 1/RC]` 不是 `[RC,1]`，断言按比值写。
4. **PySpice 与字符串网表的扫频密度**必须一致（20 点/dec）才能逐点对比。
5. **SK 带通峰值频率**：网格上的 argmax 是最近网格点（1584.89 vs f0=1591.55），对比必须同网格。
6. **蒙特卡洛良率判据**要对"名义理论值"而不是对 1.0 判：f_spec=f0 时 Butterworth 名义 |H|=0.707，按 1.0 判永远 0% 良率。
7. **瞬态幅度估计**用后 50% 稳态段极值；时间步长 tstop/2000 带来 ~0.03–0.08% 采样误差，属预期内。
8. Windows Bash 下 ngspice 交互模式（stdin 管道）不工作，批处理 `-b` 可以——批量任务一律 `-b`。

## §5 实验协议

- AC：20 点/十倍频，1 Hz–100 kHz（反相到 1 MHz）。
- 瞬态：正弦 30 周期取后 50%；阶跃 10τ。

## §7 深化设计与决策

## §8 调试战记

1. **fc 偏小 0.24%**：先疑插值（15→60 点/decade 不收敛）→ 再疑理论极点 → 终定位为 **−3.00 dB vs −3.0103 dB 判据差**，
   换算因子 √(10^0.3−1)=0.99763，残差 0.0002%。教训：先问判据定义，再查数值方法。
2. **SK 级联加载为 0**：预设「级间加载显著、需加缓冲」被数据否证——SK 每级输出由运放理想电压源驱动，天然隔离。
   补无源 RC 级联对照（3.52 dB）把故事讲实，负结果如实保留。
3. **反相宏模型极性**：B 源输入是 gm·(V+ − V−) = −gm·V(inv)（V+ = 0），首版写成 (V(inv)−V(out)) 静默错 100%，冒烟对照理论抓出。
4. **小信号斜率预测**：方波不是正弦，2πf·G·Vamp 公式不适用；改用 ΔV·2πfc（阶跃斜率上界），实测/预测同量级。
5. **Ebuf 极性**：`Ebuf mid mid2 0 0 1` 强制 mid=mid2（电压源短路语义）而非跟随；改 `Ebuf mid2 0 mid 0 1`。
6. **f0 处 C1 灵敏度 0**：数值结果意外，推导确认是精确解析对消（ω0 与 Q 随 C1 反向/同向移动），
   测试 `test_sensitivity_c1_zero_at_f0` 钉住；测试用例自身要先用 `design_sk_lp_equalR` 对齐 f0（手工 R=1e4 会偏 47%）。

# v1.2 深化轮工作记录（2026-11-11）

## §11 深化设计与决策

- 三组实验直接对着报告 §6 的未做项与 v1.1 的薄处：E16 MFB 带通（破 SK 的 Q=1/3 结构约束）、E17 `.noise` 噪声分析、E18 压摆瞬态/FPBW（v1.1 §7.5 只测了方波斜率）。
- 新增纯函数模块 3 个（`theory/mfb.py`、`theory/noise.py`、`theory/distortion.py`）+ 网表构建器 1 个（`circuits/v12_builders.py`）；54 项新单测（累计 90 全绿）。
- **协议决策**：
  - GBW 扫描的宏模型 A0 必须与理想网表的 `A_OL=1e6` 对齐，否则高 GBW 极限的残差是「两个不同 A0 之差」而非物理退化。
  - 带通峰值一律用 log-f 三次样条精化（v1.1 §7.4 插值教训），不用网格 argmax。
  - E18 用**统一频率网格**而非按各幅度归一化 FPBW：后者会把小幅度推到远超小信号闭环带宽的频率，THD 被线性衰减/数值底噪污染。
  - 运放电压噪声用「同相输入串等效电阻」变成 ngspice 真实噪声源，而不是外部解析拍一个噪声增益。

## §12 调试战记（v1.2 新增 10 条，全部已修）

1. **`.noise` 的 raw 有两段 plot**：`Noise Spectral Density Curves`（frequency / onoise_spectrum / inoise_spectrum）与 `Integrated Noise`（`v(onoise_total)` / `v(inoise_total)`，仅 1 个点且变量名带 `v()` 前缀）。v1.0 的 `find_plot("AC Analysis")` 口径不适用。
2. **温度口径**：ngspice 在 27 °C = **300.15 K** 算噪声；按 300 K 写 `4kTR` 会有 0.025% 系统偏差。`T_NGSPICE_K` 常量固定该口径。
3. **对数网格上的噪声积分**：`.noise` 输出对数扫频，线性 `np.trapezoid(d², f)` 在大间隔上高估 1/f² 尾部；改 `df = f·d(ln f)` 变量替换（`integrated_rms(log_spacing=True)`）。R=100 kΩ 的 −0.207% 残差则来自扫频下界 0.01 Hz 截断。
4. **E16 首版 GBW 退化数据非单调**、`f_dev` 恒为 −0.4182%：网格 argmax 的伪影 + 宏模型 A0=1e5 与理想网表 1e6 不对齐 + GBW 最低只到 1 MHz（相对 f0=1.6 kHz 仍高 600×）。改 200 ppd + 样条峰值 + A0=1e6 + GBW 下探 20 kHz 后严格单调，Q=10 在 20 kHz 掉 32.87%。
5. **MFB 峰值增益闭式首版推错**：写成 `2Q²√ρ/(1+ρ)`，ρ=1 时与正确式 `2Q²/(1+ρ)` 相同，冒烟只测 ρ=1 未暴露；ρ 扫描（0.25/0.5/2/4）才抓出，已改并加参数化单测。
6. **THD 精确 bin 漏谐波**：与 N5 `harmonic_ratio` 同款坑；频率非整数 bin 时 3 次谐波幅值被严重低估。改 `h·f_fund` 的 ±3 bin 邻域峰值，并加「频率故意偏移」单测。
7. **FPBW 粗网格插值不稳定**：等比频率网格给出 onset/FPBW = 1.41× / 1.61× 两幅度不一致；FPBW 附近细扫发现 THD@FPBW 仍仅 0.001%，真实 1% 起始为 1.183× / 1.165×（离散 1.51%）。教训同 v1.1 §7.4：**先固定判据与网格密度**。
8. **e_n 等效电阻必须串在同相输入**：串在信号通路会因分压改变传递函数；串在同相输入（VCVS 不取电流）AC 逐点不变，单测锁定。
9. **「最优阻抗标度 α」预设被证伪**：无源 ∝ α^0.5、e_n 恒定、i_n ∝ α¹，三项都随 α 不减 ⇒ 总噪声单调，无内点最优。脚本从「找最优 α」改为「单调性检验 + 噪声地板」，负结果如实入报告 §12.5。
10. **numpy.float64 毁网表**（v1.0 §4 历史坑）：所有新 builders 沿用 `float(x)!r`，并由 `test_netlists_are_numpy_scalar_safe` 用 `np.float64` 参数逐网表锁定。
